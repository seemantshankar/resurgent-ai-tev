# Split nomenclature into economic and frame paths

A debt-intelligence query has to find both the amounts and the furniture of a sheet — titles, annexures, section banners, period headers, footers, scale markers — because the products (CAM, CMA, ratios, dashboards, TEV chapters) are written from the database, not from the workbook. Putting that furniture on the bank cost spine would make "Year 1" and "ANNEXURE VI" look like money lines. Leaving it unnamed would force every query to re-read the grid. Each eligible cell gets one nomenclature path, on an economic root, an identity root, or a frame root. A row label shares the path of the cells it names and carries no amount role. A period header keeps a frame path; amounts under it keep their own economic paths and connect to the header by position. A formula that repeats the same fact keeps that cell's path and is a helper, so a summary sheet cannot double-count the source schedule. A formula that places one fact inside another takes the path of the fact it belongs to: the firm name at the top of an address is part of the address, and the formula only links that line to the legal-name cell. Borrower name, constitution, partners, and address are an identity root: a credit note is built from them, and they are not cost lines. Formula errors and scratch cells stay outside nomenclature.
