# Local-first OCR, page-level triage, and mandate data residency

In M1 and M2, `DocumentLayoutService` extracted digital text via PDFBox and rendered 300 DPI page PNGs for scanned pages, leaving scanned pages with zero layout blocks (`ocr_required = 1`). `DocExtractRunner` then uploaded the entire document to LlamaParse (`ParseService`) and passed the resulting cloud job to `LlamaExtractAdapter`. While this proved the cloud extraction path early, making whole-document cloud OCR the permanent default violates Epic #128's M5 routing rules, bills cloud credits for clean digital or locally readable pages, and prevents offline or data-residency-restricted mandates from completing the pipeline locally.

**Decision.**

1. **Native digital text first, local OCR second (`layout`), including standalone images and screenshots.** `DocumentLayoutService` extracts embedded text and geometry via PDFBox for every page that carries a usable digital text layer. Pages without a usable text layer and standalone image or screenshot files (`PNG`, `JPG/JPEG`, `WEBP`, `TIFF`, such as CIBIL default screenshots or portal captures) are decoded with real pixel dimensions, normalized into page rasters, and sent to `LocalOcrClient` (defaulting to local Tesseract TSV/hOCR across installed English and Indic language packs, with a deterministic fixture adapter for tests). Local OCR populates `page.ocr_engine`, `page.ocr_confidence`, `page.lang_detected`, and `block` / `span` / `table_grid` rows (reconstructing tabular grids from aligned word/line bounding boxes on both scanned pages and UI screenshots), tagging `stamp`, `signature`, and `handwriting` blocks (`is_handwritten = 1`). Previously raster-only scan or image placeholder pages (`ocr_required = 1` and `ocr_engine IS NULL`) are upgraded in place on re-layout.

2. **Image-aware and deterministic page triage (`parse`).** Before any cloud call, each page is evaluated by deterministic and pixel/confidence-backed checks — never a text-only LLM grader guessing from garbled output. A local-OCR page fails triage when any of the following hold:
   - Mean word `ocr_confidence < 0.70`, or more than 25% of numeric/amount spans have `confidence < 0.75`.
   - Non-trivial page ink density yields fewer than 20 alphanumeric/Indic characters or a high garbled-token ratio.
   - A detected table has inconsistent column counts across rows or fails printed row/column arithmetic totals.
   - Critical text or attestation overlaps handwriting (`is_handwritten = 1`) or a stamp/seal with degraded confidence.
   Each page records its routing outcome (`digital_text`, `local_ocr_kept`, `escalated_cloud`, or `local_ocr_unverified_residency_locked`) and `triage_reason` in `workspace.db`.

3. **Selective per-page cloud escalation and mandate data residency.** `mandate_policy` in `workspace.db` (plus an environment floor `TEV_DATA_RESIDENCY`) records whether a mandate is `cloud_allowed` (default) or `local_only`.
   - When `cloud_allowed`, `ParseService` escalates **only** the page indices that failed page triage to `LlamaParseClient` (`target_pages`), storing the authoritative per-page markdown/text and `parse_source` (`digital_layout` | `local_ocr` | `llama_parse`) in `workspace.db`.
   - When `local_only`, all outbound cloud calls (`LlamaParseClient`, `LlamaExtractAdapter`, remote HTTP LLM/embedding endpoints) are blocked at the adapter boundary; failing pages remain local, facts backed by low-confidence or handwritten blocks record `fact_evidence.resolution = 'ambiguous'`, dependent checklist items resolve to `unclear` (never `provided`), and `review_queue` records `ocr_low_confidence`.

4. **Unified page-backed schema extraction, multi-domain schedule lines, and local-capable embeddings.** `ExtractService` extracts pack fields, multi-column row schedules (DPR equipment & land schedules, PVsyst generation/loss tables, land lease/sale deed parcel schedules, director profile & net-worth schedules, vendor BoQs), and multi-period matrices (`financials.audited_statements`, multi-year operating tables) over the assembled per-page markdown and layout tables via a unified `ExtractClient` (`DocLlmExtractClient` with deterministic local fallback, while `LlamaExtractAdapter` remains available when explicitly selected under `cloud_allowed`). `PackPathBinder` resolves schedule and table lines per distinct `(field_key, normalized_line_key)` under the table's parent spine path. Clause and passage embeddings (`clause_embedding`, `passage_embedding`) are stored as `float32[]` blobs in `workspace.db` via `EmbeddingClient` (local deterministic vectorizer default, optional HTTP embeddings when `cloud_allowed`), and all automatic pack, clause, and checklist induction decisions are persisted in `induction_decision`.
